## 摘要（待撰寫）

隨著車載資訊系統與無線連線功能普及，車輛 Wi-Fi 介面可能成為攻擊者進入車內網路或干擾車載服務的入口。本研究針對車聯網測試場域，設計並實作一套以 Web 為操作介面的 Wi-Fi 資安測試平台，整合無線網路掃描、安全組態稽核、授權攻擊情境、無線入侵偵測（Wireless Intrusion Detection System, WIDS）及可追溯的測試紀錄。

本平台採用 Flask 與 Socket.IO 建立前後端架構，後端負責串接 `iw`、`wifite2`、`aircrack-ng`、`reaver`、`hostapd` 與 Scapy 等工具，並在缺少實體測試工具時提供模擬輸出，以支援開發與展示。系統可針對 WPS、WPA3／802.1X、PMF（802.11w）、SSID 廣播及用戶端隔離等項目進行初步稽核，並以 deauthentication、Rogue AP、WPS 測試、握手封包擷取與 PMF probe 等情境評估防護能力。

目前成果以功能原型與流程驗證為主，實體 T-BOX 測試、量化效能數據及真實工具輸出仍需於授權實驗環境中補充。研究結果預期可提供車聯網 Wi-Fi 安全測試標準化、操作集中化與證據留存的基礎。

**關鍵詞：** 車聯網、Wi-Fi 資安、WIDS、滲透測試、UN R155、ISO/SAE 21434

## 第一章 緒論

### 1.1 研究背景

- 車聯網、T-BOX 與車內 Wi-Fi 的應用情境。
- 無線介面暴露的攻擊面：未授權存取、管理框架干擾、弱認證與 Rogue AP。
- UN R155 與 ISO/SAE 21434 對資安風險管理、測試與證據追溯的需求。

### 1.2 研究動機

說明現有測試常依賴多個命令列工具、人工切換流程與分散紀錄，造成測試步驟不一致、結果不易比較及稽核證據不完整等問題。

### 1.3 研究目的

1. 建立集中式 Web 操作介面，整合掃描、稽核、攻擊測試與 WIDS 監控。
2. 將常見 Wi-Fi 安全要求轉換為可重複執行的檢查項目。
3. 以授權測試情境驗證車聯網 Wi-Fi 防護能力。
4. 建立具時間戳、分類與 JSONL 格式的測試稽核軌跡。

### 1.4 研究範圍與限制

- 研究對象為 ARTC T-BOX 測試台、實驗室 AP 與明確授權的無線目標。
- 本研究聚焦 Wi-Fi 層及其與車載測試流程的介面，不涵蓋完整車內 CAN／車載乙太網路漏洞分析。
- 現階段部分模組在缺少 Kali／Parrot 工具或監聽模式硬體時採模擬資料；實驗章須分開呈現模擬結果與實體結果。
- 所有攻擊情境僅能在書面授權的隔離環境執行。

### 1.5 論文組織

本論文共分為七章：緒論、相關技術與研究、系統需求與設計、系統實作、實驗方法與結果、討論，以及結論與未來工作。

## 第三章 系統需求與整體設計

### 3.1 使用情境與角色

- 測試工程師：選擇介面、掃描目標、執行測試與檢視結果。
- 資安分析人員：檢視 WIDS 事件與測試稽核紀錄。
- 審查／管理人員：取得可追溯的測試證據與報告。

### 3.2 功能需求

| 編號 | 功能需求 | 對應實作 |
|---|---|---|
| F-01 | 列出可用無線介面 | `modules/scan.py` |
| F-02 | 被動掃描 BSSID、SSID、頻道、訊號與加密 | `scan_networks()` |
| F-03 | 稽核 WPS、強認證、PMF、SSID 與用戶端隔離 | `modules/config_audit.py` |
| F-04 | 執行並停止授權測試工作 | `modules/attack_runner.py` |
| F-05 | 即時傳送工作輸出與狀態 | Socket.IO |
| F-06 | 啟動與停止 WIDS 監控 | `modules/wids.py` |
| F-07 | 保存測試事件與結果 | `modules/logger.py` |

### 3.3 非功能需求

- 可追溯性：每筆事件包含時間戳、層級、分類與訊息。
- 可移植性：未安裝實體工具時仍可啟動介面與模擬流程。
- 可擴充性：攻擊情境以 scenario map 管理，便於加入新測試。
- 安全性：測試範圍限定於授權環境，正式部署前需補上身分驗證、權限控管與命令參數驗證。

### 3.4 系統架構

```text
使用者瀏覽器
    │ REST API / Socket.IO
Flask 後端
    ├── Scan：iw 掃描與結果解析
    ├── Audit：Wi-Fi 組態檢查
    ├── Attack Runner：授權測試工作管理
    ├── WIDS：封包監控與事件偵測
    └── TestLogger：JSONL 稽核紀錄
    │
ARTC T-BOX／實驗室 AP／測試工具
```

### 3.5 測試流程設計

掃描目標 → 選定 BSSID → 執行基線稽核 → 選擇授權攻擊情境 → 啟動 WIDS 觀測 → 檢視即時事件 → 匯整稽核紀錄。

介紹 wifite_auto、handshake_cap、deauth、wps_bruteforce、rogue_ap、pmf_probe 的測試目的、必要參數、工作狀態與停止機制。

### 4.7 稽核紀錄與即時通訊

說明 JSONL 儲存格式、記憶體尾端查詢、Socket.IO 的 `job_update`、`job_output` 與 `wids_event` 事件。

### 4.8 安全與風險控制

記錄測試授權、隔離網段、測試資料去識別化、命令執行權限、輸入驗證與日誌保護措施。此節是正式論文必須補強的部分。

## 第五章 實驗方法與結果

### 5.1 實驗環境

| 項目 | 設定 | 待填資料 |
|---|---|---|
| 測試平台 | ARTC T-BOX／實驗室 AP | 型號、韌體版本 |
| 測試主機 | Kali／Parrot／其他 | CPU、記憶體、OS |
| 無線介面 | 監聽模式網卡 | 晶片、驅動、介面名稱 |
| 測試工具 | iw、wifite2、aircrack-ng、reaver、Scapy | 版本 |
| 網路設定 | 測試 SSID、頻道、加密方式 | 去識別化資料 |

### 5.2 實驗案例設計

| 案例 | 目的 | 主要觀測結果 |
|---|---|---|
| E-01 被動掃描 | 確認 AP 資訊可被發現與解析 | 發現數、解析正確率、耗時 |
| E-02 組態稽核 | 驗證五項檢查判定 | PASS／FAIL／WARN 一致性 |
| E-03 PMF／deauth | 評估管理框架保護 | 事件數、偵測延遲、連線影響 |
| E-04 Rogue AP | 驗證同 SSID 異 BSSID 偵測 | 告警正確性、誤報 |
| E-05 握手流程 | 驗證握手擷取與紀錄 | 成功率、耗時、紀錄完整性 |
| E-06 稽核追溯 | 驗證事件是否完整保存 | 時間戳、分類、工作 ID 關聯 |

### 5.3 評估指標

- 功能正確性：與人工檢查或已知測試設定的判定一致率。
- 偵測效能：偵測延遲、召回率、精確率與誤報率。
- 系統效能：掃描耗時、API 回應時間、同時工作數與資源使用量。
- 可追溯性：測試工作、即時輸出、事件與最終結果是否可關聯。

### 5.4 實驗結果

本節填入實驗表格、統計圖、封包或日誌截圖，並分別標示真實硬體結果與模擬資料。不得以目前的 stub 輸出作為實體網路效能結論。

### 5.5 結果分析

比較各情境的成功率、偵測能力與限制，說明哪些結果可支持研究目的，哪些結果仍需更多樣本或實體測試驗證。

## 第七章 結論與未來工作

### 7.1 結論（待補實驗數據）
